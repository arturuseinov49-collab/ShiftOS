# План развития

## 0.1 · Фундамент

- [x] Адаптивное рабочее пространство, отдельное демо.
- [x] Модель организаций, заведений, команды, меню, обучения, задач и чек-листов.
- [x] Auth/RBAC/RLS, приватное хранилище и проверка изоляции организаций.
- [x] Независимый AI gateway, контракты событий и граница vision-модуля.
- [x] Production-сборка и конфигурация запуска за HTTPS-прокси.

## 0.2 · Сценарии смены в демо

- [x] Кухня, бар, зал: ответственные, время работы, нормативы и готовность.
- [x] Задачи по участкам, назначение и распределение, результат и проверка.
- [x] Очередь заказов с действиями кухни, бара и зала.
- [x] Факты отклонений → назначенный разбор без повторов.
- [x] Приёмка, недостача, блокировка оплаты и исправленный документ.
- [x] Владелец: расходы, выручка, операционная прибыль / убыток и CSV.
- [x] Независимый контракт POS, оба демо-адаптера и идемпотентный импорт.
- [x] Разные возможности сотрудника, администратора и владельца на desktop / mobile.

Все перечисленные новые сценарии используют локальные вымышленные данные.

## 0.3 · Первая настоящая смена

- [ ] Отдельный Supabase-проект и проверка реальных Auth/Storage/PostgREST.
- [ ] Два аккаунта и две организации: сквозная проверка отсутствия чужого доступа.
- [ ] Приглашения сотрудников, безопасное назначение ролей.
- [ ] Назначение задач исполнителям и сроки выполнения.
- [ ] Запуски чек-листов, история и подтверждение выполнения.
- [ ] Редакторы команды, меню и обучения.

## Дальше · Управляющий, который помогает действовать

- [ ] Источники фактов, аудит действий, квоты и включение AI-провайдера.
- [ ] Аналитика смен, уведомления и интеграции с POS.
- [ ] Outbox, повторная доставка и идемпотентные обработчики событий.
- [ ] Отдельный vision-модуль после проработки сценариев и правил работы с данными.

Порядок последующих этапов уточняется по результатам пилота; это план, а не перечень готовых функций.
